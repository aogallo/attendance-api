# Agent Prompt — Create Organization Onboarding Specification

Use this only after the owner has approved the unresolved product decisions required for the feature and accepted the initial technical foundation.

Read `AGENTS.md`, `docs/product-decisions.md`, `docs/use-cases/principal-flow.md`, relevant domain/actor documents, `specs/organization-onboarding/intent.md`, and accepted technical decisions.

Create `specs/organization-onboarding/spec.md` as a behavior-first specification. Include scope, actors, preconditions, main flow, alternate/error flows, permission boundaries, invitation expiry/replacement, organization isolation, and stable acceptance criteria IDs (for example `OB-001`). Keep technology choices and implementation structure out of behavioral requirements unless they are part of a user-visible/API contract approved by the owner.

List any unresolved detail as an open question and state whether it blocks implementation. Do not implement code, create a technical plan, or create tasks in this step. Report the specification and wait for review.
