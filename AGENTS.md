# Agent Instructions

## Project Purpose

Attendance API v2 is a new implementation of a configurable attendance platform for organizations in different business contexts, such as schools, companies, and gyms. The shared core must remain independent of any single industry.

## Current Project State

This repository has approved technical foundations but no application implementation. Read the accepted decision index rather than reopening settled stack choices or assuming missing implementation exists. Onboarding specification and implementation-plan proposals still require their applicable approvals. The existing API v1 and client are outside this repository unless explicitly added or documented.

## Working on Features

For a new feature or behavior change:

1. Read this file and the product/technical documents relevant to the task.
2. Identify important unanswered questions. Do not silently invent product behavior.
3. Write or update the feature specification and testable acceptance criteria.
4. Propose a focused technical plan consistent with accepted technical decisions.
5. Implement only the approved scope.
6. Verify with relevant tests and checks; report exactly what ran and any limitations.

For a small, low-risk change, keep the process proportionate and avoid duplicate documentation.

## Domain Boundaries

- Keep the core industry-neutral.
- A `Person` is an individual; student, teacher, employee, and member are roles or relationships in a business context.
- Every person must have an associated schedule. The schedule belongs to the person, not the establishment, and is the reference for all lateness and schedule-compliance reports. Establishment opening hours do not replace it.
- Administrative authority and attendance participation are separate. The Platform Administrator has no attendance or schedule. An Organization Administrator may only administer, without a Person record or schedule, or also participate in attendance through an associated organization-scoped Person with a required schedule and the same attendance and reporting rules as other people.
- A confirmed `Attendance` is distinct from an unsuccessful capture attempt.
- Keep attendance identification method separate from attendance event type. Do not infer entry/exit semantics from capture sequence alone.
- Schedule comparison is for reporting and does not block an otherwise successful capture.
- Organization configuration changes apply to future captures and must not rewrite historical attendance.
- Location validation is optional. If location is unavailable, attendance may still be recorded, without claiming location validation succeeded.
- Do not introduce memberships, payroll, or access-authorization decisions into the shared core without an approved feature.
- Keep all organization data and administrative actions isolated to the correct organization.
- Use `docs/product-decisions.md` for any confirmed details and unresolved behavior.

## API v2 and API v1

- API v2 is a new implementation in this repository. Do not assume its runtime, framework, persistence, deployment topology, URL versioning, or API style before owner approval.
- The name API v2 identifies the implementation generation, not an HTTP path. It does not prescribe a `/v2` route prefix or another versioning strategy.
- The existing API v1 and client are outside this repository unless their code or authoritative contract is supplied. Do not claim to have inspected them.
- The existing client is expected to migrate to v2 later, but migration work is not part of Organization Onboarding unless explicitly approved.
- Avoid changes to the v1 system; it is outside this repository and outside scope unless explicitly provided.

## Security and Operations

- Never expose secrets or copy credentials into docs, prompts, or logs.
- Invitation tokens, administrator privileges, and organization boundaries require careful threat-aware design and tests.
- Do not add dependencies, generate code, or modify the repository during a read-only foundation analysis.
- Do not claim a command or test passed unless it was actually run and passed.
